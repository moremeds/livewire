  ## Refuted or unverifiable claims

  ### F1 — HIGH: placeholder replacement is not restart-safe

  Spec 103–115 rejects the placeholder before appending its replacement, then excludes rejected/superseded placeholders on retry. A failure between those writes
  permanently removes that event from the proposed retry population.

  Required correction: specify recoverable replacement ordering or reconciliation of incomplete pairs, including deterministic event identity and destination
  revision allocation.

  Evidence: clients/index_membership_store.py:73–77,112–129; clients/revisioned_parquet.py:45–62.

  ### F2 — HIGH: normal sync restores the supposedly drained backlog

  Spec 163–168 overlooks both existing measurement producers. Import and regular sync count every historical row with status == "unresolved", including
  superseded rows. The proposed rejected revisions leave those original rows present.

  Required correction: use the same active-event backlog definition in import, sync, and reresolve.

  Evidence: livewire_scripts/membership_sync.py:156,213,408,417,466; livewire_scripts/status.py:338–347.

  ### F3 — HIGH: an extra successful run is not harmless

  Spec 148–151 correctly identifies latest-run selection but draws the wrong conclusion. A later successful reresolve with job="membership-sync" hides a failed
  source sync, despite fetching no constituent source.

  Required correction: preserve the check’s ability to distinguish actual source synchronization from identity repair.

  Evidence: livewire_scripts/status.py:323–335.

  ### F4 — HIGH: identity and interval rules permit unsupported verification

  Spec 126–139 merges on composite FIGI alone, closes overlapping intervals by inference, and does not reconcile existing identities beyond checking the earliest
  membership date.

  The frozen contract requires compatible share-class/issuer/interval evidence and leaves material conflicts unresolved. Store validation does not enforce these
  requirements within one security ID: same-ID rows bypass collision checks.

  Required correction: define handling for contradictory identifiers, missing bounds, existing matching identities, and partial interval coverage. A successful
  date probe must be tied to the particular identity it proves; an empty probe cannot justify backdating a current record.

  Evidence: clients/security_master.py:171–187,249–259; docs/contracts/shepherd-security-identity.md:43–57,60–79.

  ### F5 — HIGH: historical source confidence is promoted implicitly

  Spec 108–109 applies the live-sync _status_for rule to all historical placeholders. Import supports confidence C/D, which remains candidate even after identity
  resolution. An unresolved row does not preserve that confidence in a dedicated field.

  Required correction: recover or explicitly validate original membership confidence before promotion. Identity verification alone does not establish membership-
  source quality.

  Evidence: livewire_scripts/membership_sync.py:50,147,185,516; clients/index_membership_store.py:43–56.

  ### F6 — HIGH: evidence commit instructions contradict the API

  Spec 84–87 calls record per response while claiming one commit per run. record() immediately calls record_many([evidence]); it does not buffer.

  Furthermore, the reused verifier checks raw bytes only. It cannot detect a failed or missing manifest commit, contrary to the safety rationale at spec 177–179.
  MDW_SOURCE_EVIDENCE is an enable/disable environment setting, not a commit target.

  Required correction: explicitly batch manifest records, commit before publishing dependent identity events, and propagate commit failure. Preserve response/
  request provenance needed to construct SourceEvidence.

  Evidence: clients/source_evidence.py:80–91,208–259,276–280; livewire_scripts/membership_sync.py:65–72; livewire_scripts/sync_corporate_actions.py:47–53,74–102.

  ### F7 — MEDIUM: currency description and acceptance check are insufficient

  The current function is _equity_currency_resolver, not _equity_currency. It chooses the greatest known_at among verified rows per symbol, without filtering
  superseded rows or effective intervals. Equal timestamps retain the first encountered row.

  Checking that a currency survives serialization does not prove the conversion caller selects the correct listing.

  Evidence: livewire_scripts/sync_corporate_actions.py:674–701; callers at 329,742.

  ## Counterexamples

  These are hypothetical state sequences derived from source, not observed market data.

  1. Interrupted migration: placeholder add P → rejected revision R commits → process stops before resolved add S. Retry selects neither superseded P nor
     rejected R. The membership is lost from current replay. Supports F1.

  2. Backlog regression: P is unresolved; R supersedes it successfully. Reresolve reports zero. The next normal sync still includes P in unresolved_ids,
     restoring WARN. Supports F2.

  3. Masked failure: weekday source sync finishes FAILED at 01:00; reresolve finishes OK at 02:00 under the same job name. The status query selects 02:00 and
     reports OK. Supports F3.

  4. Contradictory share class: two overlapping observations share a composite FIGI but have different share-class FIGIs. Assigning one security ID bypasses
     cross-security collision validation and publishes both as verified, contrary to the contract. Supports F4.

  5. Retry collision: an existing identity covers only a later part of a ticker’s history. The earliest-date skip fails; a new ID is generated with an
     overlapping interval and matching FIGI. Append raises a collision instead of extending/reusing the existing identity. Supports F4.

  6. Confidence promotion: import an unresolved non-Russell event with confidence C. Resolve its identity later. The proposed _status_for makes membership
     verified, whereas resolving during the original import would have produced candidate. Supports F5.

  7. Removal boundary: identity interval ends at time T; placeholder removal is effective at T. _resolve(..., T, ...) returns none because intervals are end-
     exclusive, although membership removal validation permits that known identity. The proposed pass leaves the removal unresolved. Evidence: clients/
     security_master.py:249–250; clients/index_membership_store.py:130–138.

  8. Duplicate historical add: regular sync adds the newly resolved ID before reresolve runs. Reresolve then inserts its historical add without reconciling the
     existing add. Set replay hides the duplication, but PIT Silver rejects “duplicate open membership interval.” Evidence: livewire_scripts/
     membership_sync.py:422–450; clients/pit_silver_revision.py:260–274.
