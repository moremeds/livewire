Worktree: `fix/systematic-ops` at starting `9d4c6bf`. Edited only `livewire_scripts/status.py` and `tests/test_status.py`; left the two untracked planning documents alone.

## Source contract and implementation

- `coverage_report.emit_coverage_measurements` creates one `now = datetime.now(UTC)` and one `LW_RUN_ID`, then emits all five `coverage_pct` and `coverage_total` rows together (`livewire_scripts/coverage_report.py:497-541`). No exact coverage numerator is persisted in the measurements ledger. The display therefore says `estimated_missing`, derived from `round(total * (1 - pct))`.
- Coverage now selects the newest observation identity per expected timeframe from either measurement name, then accepts only percentage and total with exactly the same `(scope, run_id, measured_at)`. Missing pairs, zero totals, missing expected scopes, or mixed five-scope scan identities report `UNKNOWN`; an older complete pair is not selected when a newer partial observation exists. A valid below-threshold scope or a valid scope older than the declared calendar-day allowance reports `BAD`, including when another scope has no denominator.
- Every scope displays its measured timestamp. A 12003/12004 ratio may still round to `100.0%`, but displays `estimated_missing=1/12004`. This is a derived estimate, not an observed count.
- The IB-only lag SQL still counts calendar days and retains its threshold; its output field is now `calendar_days_behind` instead of `sessions_behind`.
- The DuckDB catalog still uses `max(last_date)` per view (`clients/duckdb_catalog.py:767`); the status line now labels that value `freshest_member_last` so it cannot be mistaken for all-symbol freshness.
